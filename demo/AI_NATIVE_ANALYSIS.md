# 保E通 · 从「数字化系统」到「AI Native 中介操作系统」

> 分析对象：`demo/index.html`（v2.4.1，9 个页面，1334 行静态演示）
> 产出物：`demo/index-ai.html`（新版 AI Native 演示，10 个页面，原 demo 保留为备胎）
> 说明：新版演示中所有数字均为**模拟数据**，用于表达产品形态与价值模型，不代表真实业绩承诺。

---

## 一、现状复盘：老 demo 是什么，问题在哪

### 1.1 老 demo 的内容盘点

| 分组 | 页面 | 实际做的事 |
|---|---|---|
| 工作台 | 经营驾驶舱 | 4 个 KPI、6 个月保费柱图、保司占比环图、今日待办、一段写死的「AI 经营日报」 |
| 业务管理 | 客户管理 | 表格 + 客户抽屉（保单、跟进时间线、一段写死的「AI 建议」） |
| 业务管理 | 承保清单 | 筛选 + 明细表 + 登记表单（客户名匹配已有档案） |
| 业务管理 | 续保提醒 | 按 7/30/60 天分组，点「发送提醒」标记已发送，复制话术 |
| 业务管理 | 未成交跟进 | 状态筛选 + 一个 0–100 的「AI 意向评分」进度条 |
| 业务管理 | 理赔记录 | 状态筛选 + 登记表单 |
| 经营管理 | 渠道管理 | 渠道线索/成交/转化率表 + 条形图 |
| 经营管理 | 分成与利润 | 分成公式（首佣+续佣）×考核系数，利润构成柱图 |
| 经营管理 | 员工工作量 | 今日工作量表 + 堆叠条 |
| 横切 | 角色权限 | admin / agent / finance / ops 四角色菜单与数据范围切换 |

**结论：这是一套合格的「数字化台账系统 + 权限演示」**，做对了三件事：字段齐全、状态机清晰、权限矩阵可讲。但它不是 AI 产品。

### 1.2 六个致命问题（按严重度排序）

1. **AI 只是几段写死的文案。** 「AI 经营日报」「AI 建议」是常量字符串，点「重新生成」只弹 toast。看不出 AI 在**读什么数据、做了什么推理、依据什么**。
2. **AI 没有「行动能力」。** 全是「AI 给你一段话，你自己去干」。没有工具调用、没有多步执行、没有写回业务系统 —— 这是 Chatbot，不是 Agent。
3. **没有「AI 状态」这一类数据。** 每条保单/线索/理赔上没有 `AI 处理状态 / 置信度 / 待复核` 字段，人无法判断「这条我还要不要管」。
4. **人的角色没变。** 人还是「处理所有工单的人」，AI 只是外挂建议。AI Native 的本质是**人的角色从执行者变成例外管理者**，老 demo 完全没有体现例外队列。
5. **价值不可证明。** 没有一处回答「这套 AI 到底省了几个人、省了多少钱、ROI 多少」。采购决策者看不到账。
6. **缺合规与可解释性。** 保险是强监管行业：AI 说了什么、依据哪条条款、谁批的、留痕在哪 —— 一条都没有。这在保险行业是「不能上线」的硬伤。

一句话：**老 demo 把 AI 放进了「文案位」，新版必须把 AI 放进「工位」。**

## 二、模拟 6 个角色，看 AI 到底该赋能什么

我按中介公司的真实岗位逐一推演：他们每天的时间花在哪、痛点是什么、AI 能从哪一刀切进去、切进去之后**省下的是分钟还是人**。

### 角色 1：业务员 / 客户经理（李文博，一线，KPI 是保费和续保率）

| 时间去哪了 | 痛点 | AI 赋能点 | 可量化收益 |
|---|---|---|---|
| 40% 翻旧保单、想「该找谁聊什么」 | 不知道客户**缺什么保障**，只能靠经验推产品 | 客户 360 画像 + **保障缺口量化**（家庭结构/收入/负债/已有保额 → 缺口金额）+ 方案三档推荐 | 方案准备 40min → 3min；交叉销售转化 +20% |
| 25% 写方案、做利益演示 | 出方案靠手工套模板 | 一键生成建议书（含现金价值演示、条款引用、异议预案） | 出件时效 1 天 → 10min |
| 20% 续保催收、群发话术 | 话术千篇一律，不知道谁最可能续、什么时候打最好 | **续保概率预测 + 最佳触达时机 + 个性化话术 + 自动多轮触达** | 续保率 68% → 79%；AI 自动完成 76% 的触达 |
| 10% 客户问答（条款、免责、理赔） | 答不准、不敢答 | 条款级 RAG 问答，**答案带条款出处**，越界自动拒答转人工 | 响应秒级，合规风险下降 |
| 5% 录音复盘 | 靠自己记，没人给反馈 | 会话智能：实时辅销提示 + 结束后自动质检+复盘 | 新人上手周期 3 月 → 3 周 |

> 这个角色要的 AI 不是「会说」，是**「知道该找谁、说什么、并且能替他先说完」**。

### 角色 2：团队主管（王雅静，管 12 人，KPI 是团队达成率）

| 痛点 | AI 赋能点 | 收益 |
|---|---|---|
| 不知道谁今天要掉队，只能等周会 | **异常与例外看板**：只把「偏离剧本」的人和单推给他 | 管理动作从「管 12 人」变成「管 3 个例外」 |
| 陪访/辅导靠感觉 | AI 输出的会话质检报告 + 陪访建议 + 话术对比 | 辅导针对性提升，达标率 78% → 91% |
| 周报要手写 2 小时 | 自然语言问经营问题 → 出图 + 归因结论 | 2 小时 → 5 分钟 |

### 角色 3：运营专员（吴敏，管保单录入/续保作业/客户资料）

| 痛点 | AI 赋能点 | 收益 |
|---|---|---|
| 保单、批单、票据靠手录 | **单证 OCR + 要素抽取 + 自动校验**（保额/期限/费率/免责），异常才转人工 | 录入 15min/单 → 2min/单，准确率 99%+ |
| 续保名单靠 Excel 排 | Agent 自动分层、自动执行触达、自动回收结果 | 续保作业人力 -70% |
| 客户资料散乱、档案不完整 | 自动归档 + 缺失字段反问 + 客户合并去重 | 档案完整度 71% → 96% |

### 角色 4：核保 / 理赔岗（本轮 demo 里体现为理赔 AI 与智能核保）

| 痛点 | AI 赋能点 | 收益 |
|---|---|---|
| 健康告知看不懂、核保结论不一致 | **智能核保预审**：健康告知语义解析 → 匹配核保规则库 → 预核保结论 + 免体检额度校验 + 加费/除外建议 | 核保时效 2 天 → 4 小时；结论一致性提升 |
| 理赔单证多、责任判定靠人 | **理赔流水线**：OCR → 要素抽取 → 责任判定 → 材料缺口清单 → 反欺诈评分 → 金额预估 → 人工只做复核 | 单证处理 15min → 2min；结案 5.2 天 → 2.8 天 |
| 骗赔难识别 | 反欺诈模型（时间/金额/病史/多单交叉）给出风险分与理由 | 减损 2–5% |

### 角色 5：财务 / 精算（钱晓芸）

| 痛点 | AI 赋能点 | 收益 |
|---|---|---|
| 分成规则复杂、口径常对不上 | 规则引擎 + 自然语言问数（「9 月谁的首佣异常高」） | 核算 1 天 → 10 分钟 |
| 利润预测靠拍 | 现金流/续期佣金/退保率预测 | 预测误差下降 |

### 角色 6：合规 / 风控负责人（本 demo 新增视角）

| 痛点 | AI 赋能点 | 收益 |
|---|---|---|
| 双录与话术质检只能抽 5% | **全量 AI 质检**：敏感词、收益承诺、误导表述、未告知免责 | 覆盖率 5% → 100%，提前拦截监管风险 |
| 个人金融信息保护难审计 | 自动脱敏 + AI 操作全链路审计日志（谁让 AI 做了什么、依据什么、谁批的） | 可解释、可追溯，满足监管检查 |

### 角色 7：老板 / 决策者（周立群）

> 「我不要听 AI 能聊天。我要知道：**投进去多少钱，省出来多少人力，多签了多少保费，风险少了几分。**」

这决定了新版 demo 必须有一页 **AI 价值看板（ROI）**，并且数字要能随假设（自动化率、单价）联动。

## 三、AI Native 的五个设计原则（新版 demo 的骨架）

1. **AI 是同事，不是按钮。** 用「AI 数字员工」承载能力：有名字、有技能、有当天处理量、有自动完成率、有需要人工介入的条数。
2. **能行动，且留痕。** 每个 AI 动作都是「思考 → 调用工具 → 观察结果 → 产出物」的可视化轨迹，产出物可被人一键采纳/驳回。
3. **人是例外管理者。** 首页的核心不是 KPI，而是**「待人工决策队列」**：AI 只把低置信度、高金额、越权、异常的单子推给人。
4. **每个业务对象带 AI 状态。** 置信度、AI 是否已处理、依据来源（条款/数据）直接标在列表上，人一眼看出「这条我不用管」。
5. **价值可算账。** 每一页都指向「省了多少分钟 / 多签多少保费 / 风险降了多少」，最后一页汇总成 ROI，并且**假设可调**。

## 四、新版 demo 信息架构（`demo/index-ai.html`）

```
AI 工作台
  ├─ AI 指挥中心        AI 数字员工舰队 + 实时执行流 + 待人工决策队列 + 今日价值
  └─ Copilot 工作台     一个对话框跑完跨系统任务（计划→工具调用→产出→审批）
业务作业（AI 已接管大部分）
  ├─ 客户经营 360       保障缺口雷达 + AI 方案三档 + 建议书生成 + 会话摘要
  ├─ 续保 Agent         续保概率预测 × 分层策略 × 自动多轮触达 × A/B 话术
  ├─ 线索 Agent         智能评分与根因 + 5 分钟首触 + 自动分配路由
  └─ 理赔 AI            单证流水线（OCR→抽取→责任判定→缺口→反欺诈→金额）
风控中枢
  ├─ 核保与合规         智能核保预审 + 双录全量质检
  └─ 对话式 BI          自然语言问数 → SQL → 图表 → 归因
经营与平台
  ├─ AI 价值看板        AI 自动完成率/节省工时/人力成本/ROI（假设可调）
  └─ AI 员工管理        Agent 技能、知识库、护栏、审批权限、SLA
全局：右侧常驻 Copilot 侧栏 + ⌘K 指令中枢
```

关键页面要表达的「AI Native 时刻」：

- **指挥中心**：实时执行流在滚动（AI 正在干活），旁边就是「需要你决策的 4 件事」。管理者的动作被压缩到决策。
- **Copilot**：一句「把这个月要到期的高净值客户续保跑一遍，结果给我审」→ 自动拆解为 6 步计划、调用 5 个工具、产出 12 条待审方案。
- **理赔 AI**：单据进去，流水线一步步亮起，最后给出「责任成立、缺口 1 份材料、欺诈风险 8 分、预估赔款 24,800 元」+ 人工复核按钮。
- **对话式 BI**：输入「哪个渠道 ROI 最高」→ 展示生成的 SQL → 图表 → 归因结论 → 建议动作。
- **价值看板**：拖动「AI 自动执行比例」，节省工时/人力成本/ROI 实时重算。

## 五、降本增效的价值模型（新版 demo 中可交互复算）

**日维度（模拟）**

| Agent | 日处理 | 自动完成率 | 单件人工耗时 | 节省工时/日 |
|---|---|---|---|---|
| 续保专员 · 阿续 | 128 单 | 94% | 6 min | 9.6 h |
| 线索雷达 · 阿线 | 342 条 | 90% | 3 min（首触） | 12.4 h |
| 理赔助理 · 阿赔 | 37 件 | 86% | 14 min | 5.1 h |
| 合规质检 · 阿审 | 86 段 | 98% | 8 min | 4.6 h |
| 经营参谋 · 阿策 | 23 次 | 100% | 20 min | 2.4 h |
| 客户洞察 · 阿察 | 64 人 | 92% | 8 min | 3.2 h |
| **合计** | **680 项** | **82.4%** | — | **37.3 h/日** |

**月维度推算**：37.3 h/日 × 22 天 ≈ 820 h ≈ **4.9 FTE**；综合人力成本 ¥120/h → 月节省 **≈ ¥9.85 万**；
AI 平台 + 模型调用成本 ≈ **¥1.86 万/月** → 月净收益 **≈ ¥8.0 万**，**ROI ≈ 5.3×**，年化净收益 ≈ **¥96 万**。

**增效侧（不只是省钱）**：线索 5 分钟首触率 31%→100%、续保率 68%→79%、理赔结案 5.2→2.8 天、合规质检覆盖率 5%→100%、交叉销售转化 +23%。

> 这套模型的用意：让「AI 值不值得买」从感觉变成可辩论的算式，且每个假设都能被现场改。

## 七、手机版设计（所有 10 个页面都有对应的手机版本）

手机端不是把桌面端「缩小」，而是按「随手可用、一眼决策」重新设计的一套界面。两套界面共享同一份数据与 AI 引擎，同一套设计语言。

### 7.1 三种查看方式

| 方式 | 操作 | 用途 |
|---|---|---|
| 桌面内嵌真机框 | 顶栏点「📱 手机版」 | 演示/评审时在同一屏对比双端 |
| 真机/浏览器直接访问 | 打开 `index-ai.html?mobile=1`，或把浏览器窗口缩到 ≤ 900px | 真实手机体验 |
| 双端互跳 | 手机端「更多 → 切换到桌面版」；桌面端「手机版」 | 现场演示时自由切换 |

### 7.2 手机端专属设计决策

| 设计点 | 桌面端 | 手机端 | 为什么 |
|---|---|---|---|
| 导航 | 左侧深色分组菜单（10 项） | 底部 5 个固定 Tab（指挥中心/客户/续保/理赔/更多）+「更多」抽屉装全部 10 项 | 拇指可及、单手可完成 |
| 顶部 | 面包屑 + AI 指令中枢 + 待决策 + 通知 | 品牌 + AI 在线状态 + 头像 + 通栏「问 AI 或下指令」 | 手机上 AI 入口必须一屏可见 |
| AI 助手 | 右侧常驻侧栏（392px） | 全屏浮层 + 右下浮球（FAB），对话、执行轨迹、审批卡片纵向铺满 | 小屏放不下两栏，AI 必须占满 |
| 数据展示 | 宽表（9 列） | 卡片流：标题行（结论/状态）+ 键值行 + 底部操作按钮 | 宽表在手机上无法阅读 |
| 长文本 AI 内容 | 右对齐单元格 | 独立的「块」：小标题在上、内容在下、左对齐 | 避免长句被挤成右侧窄列 |
| 指标 | 4 列 KPI 卡 | 可横向滑动的指标条（露出半张卡，提示可滑） | 一屏内看到 3 个指标且不压缩数字 |
| 异常处理 | 卡片内 3 个按钮 | 大按钮（≥37px 高）+ 底部固定操作区 | 减少误触，两次点击内完成决策 |
| 详情 | 右侧抽屉（520px） | 全屏抽屉（全宽、圆角归零） | 充分利用小屏 |
| 流水线 | 横向 8 段 | 横向可滑动，段宽固定 | 保留流水线叙事，不换行成乱块 |
| 提示 | 顶部居中 Toast | 底部浮起 Toast（避开 Tab 栏） | 不遮挡顶部操作区 |
| 安全区 | — | `env(safe-area-inset-bottom)` 适配全面屏 | 真机不缺角 |

### 7.3 手机端 10 个页面

1. **AI 指挥中心** — 指标横滑条 → 待我决策（卡片+大按钮）→ AI 员工列表 → 实时执行流 → 价值流水 → 风险闸门
2. **Copilot 工作台** — 任务卡片（进度+一键展开轨迹）→ 工具权限 → 闸门策略 → 审计日志
3. **客户经营 360** — 客户卡片（缺口数置顶）→ 点开全屏 360（雷达图+缺口+三档方案+建议书）
4. **续保 Agent** — 续保卡片：概率/分层/归因/策略 + 「AI 自动执行」与「我来接手」双按钮
5. **线索 Agent** — 状态筛选 chips + 线索卡片（评分/归因/AI 动作）+ 打电话/发微信/升级主管
6. **理赔 AI** — 案件卡片（报损→AI 预估、风险、缺口）→ 点开全屏审核明细 + 「批准放款」
7. **核保与合规** — 双 Tab：质检卡片（点开看转写证据与处置）/ 预核保卡片（结论+依据条款）
8. **对话式 BI** — 问题 chips + 自由提问 → SQL → 图 → 归因 → 行动
9. **AI 价值看板** — 指标横滑条 + 双滑块实时复算 + 各 Agent 明细卡 + 增效对比
10. **AI 员工管理** — AI 员工卡（技能/护栏/配置）+ 闸门策略 + 审计日志

### 7.4 双端一致性

- 同一份 mock 数据、同一套「AI 状态/置信度/审批」语义
- 同一套护栏：置信度 < 70%、金额 > ¥10,000、对外发送一律需人工批准（两端都拦截）
- 同一套交互反馈：执行轨迹（思考/工具/观察/产出/待人工）、审批卡片、审计日志

## 八、落地建议（若要继续做成真系统）

| 优先级 | 事项 | 说明 |
|---|---|---|
| P0 | AI 状态字段入表 | `policies/leads/claims` 增加 `ai_status / ai_confidence / ai_evidence / reviewed_by`，否则永远是外挂 |
| P0 | 动作留痕 | 新增 `ai_actions` 表（who/agent/tool/input/output/decision/approver/timestamp），合规硬要求 |
| P1 | 工具层（Function Calling） | 先做 6 个高价值工具：查客户、查保单、生成话术、发触达、OCR 单证、问数。Agent 的价值 = 工具质量 |
| P1 | 人审闸门策略 | 按「金额 / 置信度 / 权限」三档决定自动执行 or 转人工，避免 AI 越权 |
| P2 | 知识库与 RAG 治理 | 条款、产品、合规红线分区，答案必须带出处；上线前做红队测试 |
| P2 | 价值度量埋点 | 从第一天就采集「AI 前 / AI 后」耗时与转化，否则半年后无法证明 ROI |
